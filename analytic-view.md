# Проект: планирование питания в семье

## 1. Общая идея

Окей, давай сделаем новый проект. Этот проект будет для планирования питания в семье. Суть такая: у нас должны быть разные блюда и рецепты их приготовления, а так же календарь – это основа вокруг которой будет крутиться все приложении. Члены семьи(они же пользователи), заходят на сайт и выбирают какие блюда они хотят съесть на завтрак, обед, ужин, перекус в тот или иной день календаря. Соответственно, каждый день в календаре должен быть разделён на завтрак, обед, ужин и отдельно перекус.

## 2. Блюда (картотека)

### 2.1. Поля блюда

Пользователи, могут создавать новые блюда тем самым формируя некую картотеку блюд. Каждое блюдо должно содержать какую-то картинку, иметь какое-то название(**обязательно**), описание блюда(*опционально*), состав для приготовления(*опционально*) и описание приготовления(*опционально*).

### 2.2. Метки блюда

Так же можно выбрать метку блюда: завтра, обед, ужин, перекус, причем можно выбрать несколько меток сразу. Эту метку выбирать не обязательно.

### 2.3. Управление блюдами

Каждое блюдо можно создавать вручную, либо редактировать, либо удалять.

### 2.4. Импорт информации со стороннего ресурса

При создании нового блюда пользователь должен иметь возможность подтянуть информацию о блюде со стороннего ресурса. Сторонний ресурс пусть будет https://www.iamcook.ru. То есть в карточку создания блюда нужно добавить поиск по стороннему ресурсу где пользователь может вбить название блюда, например, «паста аль помодоро» и данный поиск осуществляет запрос к внешнему ресурсу, проверяет есть ли там такой рецепт и если он есть заполняет поля нового блюда полученными данными со стороннего ресурса. В случае если на стороннем ресурсе несколько блюд с таким названием пользователю дается право выбора, какое именно блюдо нужно взять за основу

## 3. Календарь

### 3.1. Основной элемент взаимодействия

Основной элемент взаимодействия с пользователем — это именно календарь, где каждый день, должен быть разделён на завтрак, обед и ужин и отдельно секция перекус. Пользователь выбирает, например, существующий день и заполняет завтрак, обед, ужин, перекус из списка доступных блюд. Заполнение происходит при помощи выбора из предложенных вариантов блюд.

### 3.2. Правило подбора блюд по меткам

Предлагаться должны только те блюда, которые содержат соответствующую метку, а так же все блюда без единой метки. Так, например, если у нас есть два блюда: 1-ое с меткой «завтрак», а второе без меток, то когда пользователь хочет выбрать завтрак в каком-либо дне, ему предлагаются оба блюда в списке, а если он хочет выбрать обед, то ему предлагается только блюда без меток, т.к. 1-ое блюда помечено меткой завтрак.

## 4. Интерфейс

### 4.1. Общие принципы

Интерфейс должен быть максимально простым и удобным для пользователя, без перегруженных вкладок, элементов и всяких рюшечек. Ключевые особенности – это список блюд, возможность с ними работать и, собственно, календарь.

### 4.2. Вид календаря (месяц)

Лучше сделать так, чтобы изначально пользователю был виден календарь на месяц в виде сетки/таблицы где подписаны даты и выделен текущий день. В каждой ячейке календаря отобразить пункты завтрак, обед, ужин, перекус. Если в том или ином дне уже устанолвены блюда, то необходимо отобразить картинку блюда и название.

### 4.3. Просмотр дня

Пользователь может кликнуть по любому дню в календаре и «открыть» день, после чего пользователю отображается уже более подробное описание этого дня и, он может заполнять блюдами завтрак, обед, ужин, перекус. В этом месте где-нибудь нужно добавить кнопку для создания нового блюда для удобства управления. Но изначально, когда пользователь смотрит на весь календарь, он видит только информацию о днях и рационе того или иного дня.

### 4.4. Цветовая схема

За цветовую схему дизайна следует взять шесть цветов: белый, синий, голубой, светло-серый, чёрный, красный.

## 5. Пользователи и права доступа

В нашем проекте у пользователей нет никакой авторизации и разграничения прав. Любой человек, который заходит на страницу может как редактировать и изменять блюда, так и изменять рацион на каждый день. То есть у всех всё одинаково отображается на интефейсе.
