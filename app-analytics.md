# Создать приложение планирования питания с календарём и картотекой блюд

## Контекст / Проблема
Семья планирует питание «на словах» или в разрозненных заметках: нет общего места, где видно, что едим на завтрак, обед, ужин и перекус в конкретный день, и нет общей картотеки блюд с рецептами. Рецепты приходится искать и переписывать вручную с внешних сайтов.

Репозиторий `D:/Develop/AI/PI/tgu-systems-homework-2` пустой (нет ни одного коммита, ветка `trunk`). Проект создаётся с нуля. Авторизации нет: любой, кто открыл страницу, видит и редактирует всё одинаково.

## Цель
Члены семьи открывают веб-страницу с календарём на месяц, видят рацион по дням и одним кликом открывают день, чтобы выбрать блюда для завтрака, обедов, ужина и перекуса из общей картотеки. Блюда можно создавать вручную, редактировать, удалять, а также подтягивать данные рецепта с https://www.iamcook.ru по названию.

## Scope
**Входит:**
- Бэкенд (Spring Boot WebFlux + R2DBC + PostgreSQL + Liquibase) в каталоге `backend/`.
- Фронтенд (React + TypeScript + Vite) в каталоге `frontend/`.
- CRUD блюд (название, описание, состав, способ приготовления, картинка, метки).
- Календарь на месяц, детальный вид дня, назначение блюд на приёмы пищи.
- Поиск рецепта на iamcook.ru, выбор из нескольких найденных, подстановка данных в форму нового блюда.
- `docker-compose.yml` с PostgreSQL для локальной разработки.

**Не входит:**
- Авторизация, регистрация, роли, разграничение прав, аудит «кто изменил» на UI.
- Список покупок, подсчёт калорий/КБЖУ, порции, ингредиенты как отдельные сущности.
- Деплой, CI/CD, продакшн-конфигурация, HTTPS.
- Мобильное приложение, PWA, офлайн-режим, локализация (только русский язык).
- Реализации `RecipeSourceClient` для других источников, кроме iamcook.ru (сам интерфейс входит, см. п. 10).
- Автоматическое получение разрешения от iamcook.ru (см. «Зависимости и риски»).
- Перетаскивание блюд (drag-and-drop) между ячейками календаря.

## Требования

### Предметная модель
1. **Блюдо (`dish`)**:
   - `name` — обязательное, 1–200 символов;
   - `description` — необязательное, текст;
   - `ingredients` — необязательное («состав для приготовления»), многострочный текст;
   - `instructions` — необязательное («описание приготовления»), многострочный текст;
   - `image` — необязательная картинка, хранится в БД (`bytea`) вместе с `image_content_type`; допустимые типы: `image/jpeg`, `image/png`, `image/webp`; максимум 5 МБ;
   - `mealTypes` — необязательный набор меток из `BREAKFAST`, `LUNCH`, `DINNER`, `SNACK` (завтрак, обед, ужин, перекус); можно выбрать несколько или ни одной.
2. **Запись плана питания (`meal_plan_entry`)**: календарная дата (`plan_date`, тип `date`, не `Instant`, так как это день, а не момент времени), тип приёма пищи (`BREAKFAST`/`LUNCH`/`DINNER`/`SNACK`), ссылка на блюдо, порядковый номер в слоте (`position`, для стабильного порядка). В один слот (дата + тип приёма) можно добавить **несколько** блюд. Одно и то же блюдо нельзя добавить в один слот дважды (уникальный индекс `plan_date, meal_type, dish_id`).
3. Удаление блюда каскадно удаляет его записи из плана (`ON DELETE CASCADE`). Фронтенд перед удалением показывает подтверждение с текстом об этом.
4. Изменение меток блюда не затрагивает уже существующие записи плана.

### Правило предложения блюд для слота
5. Для слота типа `T` предлагаются блюда, у которых в `mealTypes` есть `T`, **и** все блюда с пустым набором меток. Блюда, у которых есть только другие метки, не предлагаются. Пример: блюдо A с меткой `BREAKFAST` и блюдо B без меток. Для завтрака предлагаются A и B, для обеда только B.
6. Правило реализуется на бэкенде: `GET /api/v1/dish?mealType=T`. Без параметра возвращаются все блюда. Бэкенд также проверяет это правило при добавлении записи в план: если блюдо не подходит слоту, возвращается `ImpossibleOperationException`.

### REST API бэкенда
7. `DishController`, `/api/v1/dish`:
   - `POST /api/v1/dish` — создать блюдо (JSON без картинки; необязательное поле `sourceImageUrl` — см. п. 12);
   - `GET /api/v1/dish?mealType=&search=` — список (необязательный фильтр по правилу п. 5 и необязательный поиск по подстроке названия, регистр не важен); сортировка по `name`; в ответе нет тела картинки, только флаг `hasImage`;
   - `GET /api/v1/dish/{id}` — одно блюдо;
   - `PUT /api/v1/dish/{id}` — обновить поля блюда (без картинки);
   - `DELETE /api/v1/dish/{id}` — удалить;
   - `PUT /api/v1/dish/{id}/image` — загрузить/заменить картинку (`multipart/form-data`, часть `file`);
   - `DELETE /api/v1/dish/{id}/image` — удалить картинку;
   - `GET /api/v1/dish/{id}/image` — отдать байты картинки с корректным `Content-Type` и `Cache-Control`; 404, если картинки нет.
8. `MealPlanController`, `/api/v1/meal-plan`:
   - `GET /api/v1/meal-plan?from=YYYY-MM-DD&to=YYYY-MM-DD` — записи плана за период включительно (максимум 62 дня, иначе `BadRequestException`); в каждой записи `id`, `date`, `mealType`, `position`, краткая информация о блюде (`dishId`, `dishName`, `hasImage`);
   - `POST /api/v1/meal-plan` — добавить блюдо в слот (`date`, `mealType`, `dishId`); `position` назначается как «последний + 1»;
   - `DELETE /api/v1/meal-plan/{id}` — убрать блюдо из слота.
9. `ExternalRecipeController`, `/api/v1/external-recipe`:
   - `GET /api/v1/external-recipe/search?query=...` — поиск через активный источник рецептов (сейчас iamcook.ru), возвращает список `{ id, title, imageUrl }` (максимум 10 результатов); пустой список, если ничего не найдено; `query` — обязательный, не короче 2 символов;
   - `GET /api/v1/external-recipe?id=...` — загрузить рецепт по `id` из результатов поиска и вернуть `{ id, title, description, ingredients, instructions, imageUrl }`. Формат `id` определяет источник; для iamcook.ru это числовой идентификатор из `/showrecipe/<id>`, иначе `BadRequestException`. Клиент передаёт именно `id`, а не произвольный URL, и бэкенд сам строит адрес запроса (защита от SSRF).
10. **Источник рецептов подключаемый.** Вся работа с внешним ресурсом скрыта за интерфейсом `service/external/RecipeSourceClient`:
    - `Flux<ExternalRecipeSearchItem> search(String query, int limit)`;
    - `Mono<ExternalRecipe> getById(String id)`;
    - `Mono<ExternalImage> downloadImage(String imageUrl)` (байты и content type; реализация сама проверяет, что адрес принадлежит её источнику);
    - `String getSourceName()` (для логов и сообщений об ошибках).
    Сервис (`ExternalRecipeService`) и контроллер зависят только от интерфейса и не знают про iamcook.ru. Единственная реализация в рамках задачи — `IamcookRecipeSourceClient` (`service/external/iamcook/`). Активный источник выбирается свойством `app.external-recipe.source` (значение `iamcook`; регистрация через `@ConditionalOnProperty` или фабрику по имени). Модели `ExternalRecipeSearchItem`, `ExternalRecipe`, `ExternalImage` — собственные, не привязанные к формату iamcook.ru, чтобы можно было добавить другой источник (например TheMealDB или Spoonacular) без изменения сервиса, контроллера и фронтенда. Остальные пункты ниже описывают `IamcookRecipeSourceClient`.
11. Вызовы к iamcook.ru выполняются через `WebClient` (неблокирующе), с таймаутом (по умолчанию 10 с, настраивается через `app.external-recipe.*`), заголовком `User-Agent`, парсинг HTML — `jsoup` (в `Mono.fromCallable(...).subscribeOn(Schedulers.boundedElastic())` либо иным не блокирующим event loop способом). Недоступность сайта или изменение его вёрстки → `ExternalServiceException` (новая, наследник `CalendarException`) → HTTP 502 с `userMessage` «Не удалось получить данные с iamcook.ru. Попробуйте позже или заполните блюдо вручную».
12. При создании блюда с `sourceImageUrl` бэкенд скачивает картинку через `RecipeSourceClient.downloadImage` (для iamcook.ru только с хостов `*.iamcook.ru`, ограничение размера 5 МБ, проверка типа) и сохраняет в БД. Если скачать картинку не удалось, блюдо всё равно создаётся без картинки, а в лог пишется `warn`.
13. Исходящие запросы к iamcook.ru ограничить: не чаще одного запроса в секунду (общий лимит на экземпляр приложения), только по действию пользователя, без фонового обхода; в запросах указывать `User-Agent` с названием приложения. Лимит настраивается в `app.external-recipe.min-request-interval`.
14. Структура iamcook.ru **проверена автором задачи 2026-10-31** (см. подраздел «Результаты анализа iamcook.ru» в «Технических деталях»). Перед реализацией исполнитель кратко перепроверяет её на живом сайте, так как вёрстка могла измениться. Селекторы и пути вынести в `@ConfigurationProperties` (`app.external-recipe.*`), HTML-фикстуры для тестов сохранить в `backend/src/test/resources/external-recipe/`.

### Нефункциональные
15. Весь бэкенд следует правилам проекта: слои `controller → service → dao`, entity наружу не отдаются, отдельные Request/Response DTO с `@Schema`, MapStruct, Lombok, `BaseEntity` с аудит-полями, `@Transactional` на записи, цепочки начинаются с `Mono.deferContextual(Mono::just)`, без `block()` и `Thread.sleep`.
16. Аудит-поля `create_user`/`last_modify_user` заполняются из Reactor Context: `ReactiveContextFilter` кладёт `requestId` и `clientId`; `clientId` берётся из заголовка `X-Client-Id`, если его нет — значение `anonymous`. Авторизации нет.
17. Все пользовательские сообщения, комментарии, Javadoc, логи — на русском; `message` исключений — на английском, `userMessage` — на русском.
18. Максимальный размер multipart-запроса — 6 МБ (настройка Spring), ошибка превышения → HTTP 413 через `GlobalExceptionHandler` с `userMessage`.
19. Документация API доступна через springdoc (`/swagger-ui.html`).
20. Фронтенд обращается к бэкенду только по относительному пути `/api/v1/...`; в dev-режиме Vite проксирует `/api` на `http://localhost:8080` (CORS на бэкенде не настраивается).

## Критерии приёмки

**Блюда**
- Given пустая картотека, When пользователь создаёт блюдо только с названием «Омлет», Then блюдо сохранено и появляется в списке блюд.
- Given форма блюда, When пользователь оставляет название пустым и нажимает «Сохранить», Then блюдо не создаётся, под полем показано «Введите название блюда», запрос на сервер не уходит; а прямой `POST /api/v1/dish` с пустым `name` возвращает 400 с `userMessage`.
- Given блюдо с картинкой, When пользователь меняет метки на «Завтрак» + «Перекус» и сохраняет, Then при повторном открытии отмечены обе метки.
- Given блюдо в картотеке, When пользователь нажимает «Удалить» и подтверждает, Then блюдо исчезает из списка и из ячеек календаря; при отказе в подтверждении ничего не меняется.
- Given файл картинки больше 5 МБ или не jpeg/png/webp, When пользователь его загружает, Then картинка не сохраняется, показано понятное сообщение об ошибке на русском.

**Предложение блюд**
- Given блюдо A с меткой «Завтрак» и блюдо B без меток, When пользователь добавляет блюдо в завтрак, Then в списке выбора A и B.
- Given те же блюда A и B, When пользователь добавляет блюдо в обед, Then в списке выбора только B.
- Given блюдо A с меткой «Завтрак», When выполняется `POST /api/v1/meal-plan` с `mealType=LUNCH` и `dishId` блюда A, Then ответ 422 с `userMessage`, запись не создана.

**Календарь**
- Given открыта главная страница, When она загрузилась, Then показан календарь текущего месяца в виде сетки (понедельник — первый день недели), подписаны даты, текущий день выделен, в каждой ячейке есть четыре строки: «Завтрак», «Обед», «Ужин», «Перекус».
- Given на 15-е число в обед добавлены два блюда, When пользователь смотрит календарь, Then в ячейке 15-го в строке «Обед» отображены картинка и название этих блюд (блюда без картинки показываются с названием и нейтральной заглушкой).
- Given календарь, When пользователь нажимает «←»/«→» рядом с названием месяца, Then отображается предыдущий/следующий месяц, а кнопка «Сегодня» возвращает к текущему.
- Given календарь, When пользователь кликает по любому дню, Then открывается детальный вид этого дня с четырьмя секциями и кнопками «Добавить» в каждой.
- Given детальный вид дня, When пользователь добавляет блюдо в слот и затем нажимает «×» у блюда, Then блюдо появляется в слоте и затем исчезает, а календарь при возврате отражает изменения.
- Given блюдо уже есть в слоте, When пользователь открывает выбор блюд для того же слота, Then это блюдо в списке выбора отсутствует или помечено недоступным (повторно добавить нельзя), а прямой `POST` дубликата возвращает 422.
- Given период больше 62 дней, When вызывается `GET /api/v1/meal-plan?from=2026-01-01&to=2026-12-31`, Then ответ 400 с `userMessage`.

**Внешний ресурс**
- Given форма создания блюда, When пользователь вводит «паста аль помодоро» и нажимает «Найти», Then показан список найденных рецептов iamcook.ru (картинка + название); при единственном результате он тоже показывается в списке и требует выбора.
- Given список найденных рецептов, When пользователь выбирает один, Then поля формы (название, описание, состав, приготовление, картинка) заполнены полученными данными и их можно редактировать до сохранения; уже введённые вручную поля перезаписываются только после подтверждения.
- Given поиск без результатов, When пользователь нажимает «Найти», Then показано «Ничего не найдено. Заполните блюдо вручную».
- Given iamcook.ru недоступен (таймаут/ошибка), When пользователь нажимает «Найти», Then показано сообщение из `userMessage` (HTTP 502), форма остаётся доступной для ручного заполнения.
- Given `GET /api/v1/external-recipe?id=../../etc/passwd` (или любой `id`, не состоящий из цифр), When запрос выполняется, Then ответ 400 и никаких исходящих запросов не выполняется.

## Дизайн

### Общие принципы
Интерфейс максимально простой: без лишних вкладок, иконок-украшений, анимаций и теней. Только то, что нужно: календарь и список блюд. Язык интерфейса — русский. Макетов нет, ниже описание словами; исполнитель не должен добавлять экраны и элементы, которых здесь нет, без согласования.

### Цветовая схема (строго 6 цветов)
Определить как CSS-переменные в `frontend/src/styles/theme.css` и не использовать других цветов (допустимы только прозрачность/`opacity` этих цветов):

| Назначение | Цвет | HEX |
|---|---|---|
| Фон страницы и карточек | белый | `#FFFFFF` |
| Основной цвет: кнопки, шапка, ссылки, выделение сегодняшнего дня (рамка) | синий | `#1F5FBF` |
| Вторичный акцент: фон выбранных меток, hover, фон заголовков секций | голубой | `#CFE6FA` |
| Границы, фон ячеек вне текущего месяца, заглушки картинок, disabled | светло-серый | `#E6E8EB` |
| Текст | чёрный | `#111111` |
| Ошибки, кнопка «Удалить», обязательные поля | красный | `#D32F2F` |

Контраст текста и фона должен быть не ниже 4.5:1 (синий на белом и белый на синем проходят).

### Каркас
- Сверху узкая шапка (белая, нижняя граница светло-серая) с двумя ссылками: «Календарь» (главная, `/`) и «Блюда» (`/dishes`). Активная ссылка — синяя с подчёркиванием.
- Страницы (маршруты, `react-router`):
  - `/` — календарь месяца;
  - `/day/:date` — день (`YYYY-MM-DD`);
  - `/dishes` — список блюд;
  - `/dishes/new` — создание блюда;
  - `/dishes/:id/edit` — редактирование блюда.
- Некорректная дата в `/day/:date` → сообщение «Некорректная дата» и ссылка на календарь.

### Экран «Календарь» (`/`)
- Заголовок: «Октябрь 2026» + кнопки «←», «→», «Сегодня».
- Сетка 7 колонок (Пн … Вс) с подписями дней недели. Ячейка = один день:
  - в углу номер дня; дни другого месяца — на светло-сером фоне, без блюд, не кликабельны; сегодняшний день — синяя рамка 2 px и синий номер;
  - внутри четыре строки: «Завтрак», «Обед», «Ужин», «Перекус» (подпись мелким текстом). В строке блюда показываются как миниатюра картинки (32×32, `object-fit: cover`) + название (обрезка многоточием в одну строку); если блюд несколько, показываются подряд, при нехватке места — «+N»;
  - пустая строка — только подпись, без заглушек;
  - клик по ячейке → `/day/<дата>`. Ячейка — `<a>`/кнопка, доступна с клавиатуры (Tab, Enter), `aria-label` вида «15 октября, открыть день».
- Состояния: загрузка — серый скелетон сетки; ошибка загрузки — красный текст «Не удалось загрузить календарь» + кнопка «Повторить»; пусто — обычная сетка без блюд.
- На узких экранах (< 768 px) сетка превращается в вертикальный список дней (адаптивность минимальная, но без горизонтальной прокрутки).

### Экран «День» (`/day/:date`)
- Заголовок: «Пятница, 15 октября 2026», кнопки «← Предыдущий день», «Следующий день →», «К календарю».

### Результаты анализа iamcook.ru (проверено 2026-10-31)

- Страницы отдаются в UTF-8, кодировка сайта не cp1251.

Если отправить его в неверной кодировке, сервер вернёт `200` с PHP `Fatal error` в блоке `<div id="advsearch">`; это нужно считать ошибкой (`ExternalServiceException`), а не пустым результатом. Заголовки `User-Agent` и `Referer: https://www.iamcook.ru/` рекомендуются.
- **Разбор результатов поиска** (внутри `<div id="advsearch">`): счётчик в `p.scnotice` («…найдено рецептов: N»), при нулевом результате блока карточек нет. Каждая карточка — `div.recblockwide`: ссылка `a[href^="/showrecipe/"]`, название `div.header a`, миниатюра `img.preimage` (`src` вида `//img.iamcook.ru/...`, без схемы, добавить `https:`), краткое описание `div.description`, ингредиенты `div.ingrlayer`. Эти же данные можно использовать для превью в списке выбора.
- **Страница рецепта:** `GET https://www.iamcook.ru/showrecipe/<id>`:
  - название `#recbody h1`;
  - описание `div.recdescription` (внутри `span`);
  - ингредиенты `div.ingredients div.ilist` (абзацы `p`, подзаголовки типа «Соус:» в `strong`), собирать в многострочный текст «по строке на ингредиент»;

## Зависимости и риски
- **Блокеров нет**, но есть риски:
  - **iamcook.ru — внешний сайт без публичного API.** Парсинг HTML хрупок: изменение вёрстки сломает импорт. Митигация: селекторы в конфигурации, тесты на HTML-фикстурах, понятная ошибка 502 и возможность создать блюдо вручную. Запросы только по действию пользователя с лимитом частоты (п. 13).
  - **Юридический риск (решение владельца: продолжаем с iamcook.ru).** Пользовательское соглашение сайта (https://www.iamcook.ru/files/user-agreement.pdf, редакция от 12.02.2026) запрещает без письменного разрешения Администрации использовать боты/краулеры для сбора информации (п. 6.3.8) и автоматизированный сбор рецептов, фото и описаний для формирования собственного каталога (п. 6.3.16); права на рецепты и фото принадлежат их авторам (п. 5.17). Наш импорт формально подпадает под эти пункты. Практический риск для закрытого семейного приложения невелик, но возможна блокировка по IP. Исполнитель код не блокирует, но **не публикует приложение публично**, не добавляет массовый/фоновый импорт и в `README.md` указывает это ограничение. Получение письменного разрешения через https://www.iamcook.ru/contacts — отдельное действие владельца вне этой задачи.
  - **Замена источника.** Из-за юридического риска и отсутствия у iamcook.ru API источник должен заменяться без переписывания сервиса и фронтенда; для этого введён `RecipeSourceClient` (п. 10). Рассмотренные официальные API (TheMealDB, Spoonacular) только на английском языке (Spoonacular — `en`/`de`), поэтому в эту задачу не вошли.
  - **Сайт без капчи, поиск и страницы рецептов отдаются обычным HTML**, поэтому браузерная автоматизация не нужна. Если при перепроверке выяснится, что это изменилось (капча, 403, данные только через JS), исполнитель **останавливается** и сообщает об этом, не подключая браузерную автоматизацию без согласования.
  - **Подводные камни поиска** (см. «Результаты анализа»): тело запроса обязательно в UTF-8, иначе сервер падает с PHP-ошибкой в теле ответа при коде 200; пути `/search` закрыты в `robots.txt`, использовать их нельзя.
  - **Сертификат:** сайт использует Let's Encrypt. Системный `curl` в среде автора ему не доверял (неполная цепочка локального набора CA), в JVM проблем не ожидается, но проверить. Отключать проверку сертификата в коде запрещено.
  - **Картинки в БД** увеличивают размер базы. Для семейного объёма допустимо (лимит 5 МБ). Списковые запросы не должны выбирать колонку `image`.
  - **Нет авторизации**: любой, кто видит сервис, может всё менять. Принято осознанно, в рамках задачи не решается.
  - **SSRF** через параметр `url` — закрывается проверкой хоста (п. 9, 11).
  - Одновременное редактирование одного дня двумя пользователями: «последний выигрывает», блокировок нет; клиент перезапрашивает данные при возврате на страницу.
- Связанных задач нет.
